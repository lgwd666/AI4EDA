# UART 重复输出与周期写提交调试记录

> 日期：2026-11-24  
> 阶段：一生一芯 E6  
> 涉及模块：`npc/csrc/main.cpp`、`npc/csrc/pmem.cpp`、`npc/csrc/pmem.h`  
> 约束：本次只修改仿真环境，不修改 NPC RTL

## 1. 问题背景

在 NPC 上运行 `am-kernels/kernels/hello` 时，UART 能输出字符串，但一个字符会被打印多次：

```text
HHHeeellllllooo,,,   AAAbbbssstttrrraaaccctttMMMaaaccchhhiiinnneee!!!
```

UART 的软件链路本身正确：

```text
putch()
  -> sb 写 0x10000000
  -> LSU 调用 pmem_write()
  -> UART 行为模型执行 fputc()
```

问题集中在 `pmem_write()` 的调用次数和调用时机，而不是 `putch()` 的字符数据。

## 2. 根因：组合逻辑中的 DPI 副作用

当前 `LSU.sv` 在组合逻辑中调用写函数：

```systemverilog
always @(*) begin
  if (mem_valid) begin
    rdata = pmem_read(mem_addr);
    if (mem_wen) begin
      pmem_write(mem_addr, mem_wdata, mem_wmask);
    end
  end
end
```

`pmem_read()` 没有副作用，重复读取通常不影响结果；但 `pmem_write()` 会修改 PMEM 或输出字符，是有副作用的调用。

Verilator 对组合逻辑求值时：

1. 同一次 `eval()` 可能多次执行组合逻辑，直到信号稳定。
2. 求值中间态可能短暂出现 `mem_valid/mem_wen` 和旧地址的组合。
3. 时钟高、低两个阶段的 `eval()` 都可能调用组合逻辑中的 DPI 函数。

对普通 PMEM 来说，相同数据重复写通常是幂等的，所以问题不明显；对 UART 来说，每次调用都会多打印一个字符，副作用直接可见。

## 3. 第一种方案：按 STORE 指令过滤

此前仿真环境通过 `debug_inst` 判断当前指令是否为 STORE，并让同一条指令只输出一次。

这种方案在当前单周期 NPC 上能得到正确字符串，但存在不合理的功能耦合：

- UART 设备模型依赖了调试接口和指令编码。
- `debug_inst` 应服务于 DiffTest、日志和调试，不应决定设备功能。
- 多周期或流水线中，当前 debug 指令不一定就是发起 LSU 写请求的指令。
- 它掩盖了“组合逻辑重复触发副作用”的真正问题。

因此需要改成只依赖仿真时钟和写请求的方案。

## 4. 第二种方案：每周期只接受一次写

### 4.1 按周期去重

在每个 `single_cycle()` 开头清除“本周期已写”标志，一个周期内只接受第一次 `pmem_write()`。

实测输出由每个字符三次变成两次：

```text
HHeelllloo,,  AAbbssttrraaccttMMaacchhiinnee!!
```

这说明它只能消除同一周期内的重复调用，不能消除跨周期瞬态写。

### 4.2 只在高电平阶段接受第一次写

进一步把写窗口放在高电平 `eval()` 前：

```text
clk=0 eval：禁止写
clk=1 eval：接受第一次写
```

结果仍然是每个字符两次。增加临时阶段日志后，可以观察到以下关键现象：

| 当前真实指令 | 低电平阶段的 UART 调用 | 高电平阶段的 UART 调用 | 解释 |
|---|---|---|---|
| 前一条非 STORE 指令 | 无 | 有 | 组合信号瞬态造成的多余调用 |
| 真正的 `sb` | 有 | 有 | 有效写请求在低、高电平求值中均存在 |

因此，“高电平第一次调用”不一定就是有效写。它可能先接受前一个非 STORE 周期中的瞬态写，随后真正 `sb` 周期的写又被去重条件挡住。

这次尝试说明：只限制次数还不够，还需要一个与指令无关的有效写确认条件。

## 5. 最终方案：低电平确认，高电平单次提交

利用上述实测时序，在每个周期中先观察低电平写请求，再允许高电平提交。

### 5.1 仿真驱动顺序

`main.cpp` 中的 `single_cycle()` 调整为：

```cpp
static void single_cycle() {
  pmem_begin_cycle();

  dut.clk = 0;
  dut.eval();
  dump();

  pmem_begin_write();
  dut.clk = 1;
  dut.eval();
  dump();

  pmem_end_write();
}
```

各阶段含义：

```text
pmem_begin_cycle()
  清除本周期的“观察到写”和“已经提交”状态

clk=0 eval()
  只记录是否出现写请求，不执行 PMEM/UART 副作用

pmem_begin_write()
  打开本周期的写提交窗口

clk=1 eval()
  如果低电平观察到写，则本周期最多提交一次

pmem_end_write()
  关闭写窗口
```

### 5.2 环境内部状态

仿真环境只维护三个与写事务有关的状态：

- `write_enabled`：当前是否处于高电平写提交窗口。
- `write_observed`：本周期低电平阶段是否观察到写请求。
- `write_committed`：本周期是否已经提交过一次写。

`pmem_write()` 的控制逻辑为：

```cpp
if (!write_enabled) {
  write_observed = true;
  return;
}
if (!write_observed || write_committed) {
  return;
}
write_committed = true;

// 根据 addr 写 UART 或 PMEM
```

最终方案不再读取 PC、`debug_inst` 或 opcode。UART 和 PMEM 使用同一个写提交规则。

### 5.3 为什么能解决本次重复输出

- 非 STORE 周期只有高电平瞬态写，没有低电平有效写，因此 `write_observed=false`，不会提交。
- 真正的 STORE 在低电平已经存在写请求，因此 `write_observed=true`。
- 高电平可能多次调用，但 `write_committed` 保证只提交一次。
- PMEM 写和 UART 写都在同一个周期边界提交，行为一致。

## 6. 验证结果

### 6.1 UART 与 DiffTest

运行新构建的 `build/NPC` 和现有 `hello-minirv-npc.bin`：

```text
Hello, AbstractMachine!
mainargs = ''.
HIT GOOD TRAP: pc=0x800004a8, a0=0
```

每个字符只输出一次，DiffTest 无差异。

### 6.2 普通 PMEM 写回归

直接运行现有 CPU 测试镜像：

```bash
build/NPC ../am-kernels/tests/cpu-tests/build/add-minirv-npc.bin
build/NPC ../am-kernels/tests/cpu-tests/build/matrix-mul-minirv-npc.bin
build/NPC ../am-kernels/tests/cpu-tests/build/recursion-minirv-npc.bin
```

结果：

```text
add        HIT GOOD TRAP
matrix-mul HIT GOOD TRAP
recursion  HIT GOOD TRAP
```

说明写窗口没有丢失普通存储器写，包含大量 LOAD/STORE 的程序仍与 REF 一致。

### 6.3 周期计时器回归

```bash
NPC_MAX_CYCLES=110000000 \
  build/NPC ../am-kernels/tests/am-tests/build/amtest-minirv-npc.bin
```

结果：

```text
1900-0-0 00:00:00 GMT (1 second).
NPC TEST FAIL: ebreak not reached
```

计时功能正常。`rtc_test()` 是无限循环，随后达到周期上限属于预期行为。

## 8. 方案边界与后续 RTL 修正

当前方案是针对现有仿真驱动的临时事务调度，不是 UART 对指令的特殊处理，也不是最终 RTL 结构。

它依赖当前单周期 NPC 的以下特征：

- 一个周期最多有一个写事务。
- 有效写请求在低电平组合求值阶段能够被观察到。
- 高电平阶段只需要提交一次。

将来如果出现多写端口、一个周期多个写事务或不同的总线握手协议，不能继续简单使用“每周期一次”的限制。

后续应在 RTL 中把有副作用的写调用放到明确的时钟边沿，例如：

```systemverilog
always_ff @(posedge clk) begin
  if (rst_n && mem_valid && mem_wen) begin
    pmem_write(mem_addr, mem_wdata, mem_wmask);
  end
end
```

完成 RTL 修正后，可以删除 `write_observed/write_committed` 和写窗口控制，让 `pmem_write()` 恢复为只按地址、数据和掩码工作的纯设备行为模型。
