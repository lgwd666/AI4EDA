# P0 日间学习 01：状态机模型

> 建议用时：20~25 分钟。本单元不需要服务器。
>
> 官方讲义：[F4 计算机系统的状态机模型](https://ysyx.oscc.cc/docs/2607/f/4.html)。本单元选取其中的“存储程序 → 状态机四要素 → ISA/C 程序/数字电路的联系”作为主线。
>
> 学完目标：能用一段指令序列的状态变化解释处理器工作，并说清 ISA、模拟器和 RTL 处理器之间的关系。

## 1. 先让一段程序跑起来，再谈状态机

处理器不是靠自己“思考”该做什么，而是机械地执行指令。一条指令至少要说明两件事：

- **操作码（opcode）**：做什么，例如相加、装入立即数或跳转。
- **操作数（operand）**：对哪些数据做，例如源寄存器、目的寄存器和立即数。

官网 F4 先定义了一个只有 3 条指令的迷你 ISA，称为 `sISA`：

| 指令 | 含义 |
|---|---|
| `li rd, imm` | `R[rd] ← imm` |
| `add rd, rs1, rs2` | `R[rd] ← R[rs1] + R[rs2]` |
| `bner0 rs2, addr` | 如果 `R[rs2] != R[0]`，则 `PC ← addr` |

程序就是一段指令序列。把指令放进内存，再用 PC 指示当前执行位置，处理器只需重复：

```text
根据当前 PC 取指 → 执行指令 → 更新 PC
```

这就是**存储程序**的基本思想。普通指令让 PC 顺序前进，`bner0` 则可以改变下一条指令的位置，从而形成循环。

## 2. 亲自扮演一次处理器

下面是官网的数列求和程序，计算 `1+2+...+10`：

```asm
0: li  r0, 10
1: li  r1, 0
2: li  r2, 0
3: li  r3, 1
4: add r1, r1, r3
5: add r2, r2, r1
6: bner0 r1, 4
7: bner0 r3, 7
```

用 `(PC, r0, r1, r2, r3)` 记录每次指令执行后的状态：

```text
(0,  0, 0, 0, 0)  # 初始状态
(1, 10, 0, 0, 0)  # li r0, 10
(2, 10, 0, 0, 0)  # li r1, 0
(3, 10, 0, 0, 0)  # li r2, 0
(4, 10, 0, 0, 1)  # li r3, 1
(5, 10, 1, 0, 1)  # r1 = 0 + 1
(6, 10, 1, 1, 1)  # r2 = 0 + 1
(4, 10, 1, 1, 1)  # r1 != r0，跳回 PC=4
(5, 10, 2, 1, 1)  # 第二次执行 PC=4
(6, 10, 2, 2, 1)  # 第二次执行 PC=5
......
```

这里最重要的不是求和结果，而是观察：**每条指令都把一组确定的状态变成下一组确定的状态。** PC 不一定递增，跳转指令可以直接改变状态序列。

## 3. 状态机的四个要素

官网 F4 用四个部分描述状态机。把它们对应到 ISA：

| 要素 | 在 ISA 中的含义 | 上面的例子 |
|---|---|---|
| 状态集合 | PC、通用寄存器和内存所有可能取值的组合 | `(PC, r0, r1, r2, r3, M)` |
| 激励事件集合 | 让状态发生变化的事件 | 执行一条指令 |
| 状态转移规则 | 在某个状态下执行某条指令后得到什么次态 | 每条指令的语义 |
| 初始状态 | 尚未执行指令时的状态 | `PC=0`，各寄存器和内存有确定的初始值 |

对当前 P0 的迷你 RISC-V 处理器，最小 ISA 状态仍可先关注三类：

- **PC**：当前待取或待执行指令的地址；指令提交后得到下一 PC。
- **通用寄存器**：保存指令的源操作数和运算结果；RISC-V 的 `x0` 恒为零。
- **内存**：保存程序指令以及 load/store 访问的数据。

CSR、特权级和异常相关状态后续再加入。ALU 内部信号、流水线寄存器、cache 标签等属于具体实现，不直接写入当前最小 ISA 状态清单。

## 4. 为什么 C 程序、ISA 和数字电路可以统一理解

官网 F4 不只把 ISA 看成状态机，还用同一视角理解 C 程序和数字电路：

| | 状态 | 激励事件 | 状态转移规则 |
|---|---|---|---|
| C 程序 | 变量，以及当前执行到哪条语句的位置 | 执行一条语句 | 语句的语义 |
| ISA | PC、通用寄存器、内存 | 执行一条指令 | 指令的语义 |
| 数字电路 | 时序逻辑元件保存的信息 | 组合逻辑产生的次态信号 | 组合逻辑决定的次态 |

由此得到两条重要关系：

- **编写指令集模拟器**：用 C 程序的变量和语句实现 ISA 的状态及指令语义。
- **设计 CPU**：用时序逻辑和组合逻辑实现 ISA 的状态及指令语义。

因此，模拟器和 RTL 不是两个无关项目，而是同一个 ISA 状态机的不同实现。内部周期数、流水线结构和控制信号可以不同，但每条指令提交后的软件可见结果必须遵循同一 ISA。

## 5. 这个视角怎样帮助调试

如果被测设计（DUT，RTL 实现）和参考模型（REF，模拟器）从相同初始状态执行相同指令序列，那么在每条指令的修改全部生效之后，也就是**提交边界**，两者的 ISA 状态应当一致。单元 03 会按官网 E4 展开这一方法。

例如执行 `addi x1, x0, -1` 后：

```text
REF: x1 = 0xffffffff
DUT: x1 = 0x00000fff
```

状态差异先把调查范围缩小到这条指令及立即数扩展附近，再有针对性地查看内部波形。首个差异是调查起点，不一定是根因；有限测试也不能证明所有情况都正确。

官网 F4 最后还强调一种工作方式：系统的每次状态转移都应有手册依据。遇到不理解的机器行为，先回到手册和证据，而不是先猜测“工具坏了”。
