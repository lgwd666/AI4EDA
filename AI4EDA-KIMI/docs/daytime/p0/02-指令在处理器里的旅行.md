# P0 日间学习 02：指令在处理器里的旅行

> 建议用时：20~25 分钟。本单元不需要服务器。
>
> 学完目标：能沿“取指 → 译码 → 执行 → 访存 → 写回”解释 P0 的 8 条指令，并单独说明 PC 如何更新。

## 1. 五个功能步骤，不等于已经实现了五级流水线

先把一条指令分成五个**功能步骤**：

```text
IF  取指      从 PC 指向的内存读取指令
ID  译码      识别操作，读取寄存器，生成立即数
EX  执行      算术运算、地址计算或跳转目标计算
MEM 访存      load/store 访问数据内存，其他指令直接通过
WB  写回      把结果写入目标寄存器 rd
```

这些功能步骤与 P0 的 RTL 模块名对应：IF/ID/EX 对应 IFU/IDU/EXU，MEM 对应 LSU，WB 对应 WBU。

这是一条指令的逻辑旅程。单周期处理器可以在一个周期内完成全部步骤，多周期处理器可以分多个周期完成，流水线处理器则让多条指令在这些步骤上重叠执行。

所以，能讲出这五个步骤，不代表已经理解了流水线冒险；P0 先把一条指令走通。

## 2. IF：PC 指向哪里，就从哪里取指

当前迷你 RV 指令长度都是 32 位，也就是 4 字节。取指阶段使用当前 PC 读取指令：

```text
instruction = mem[pc .. pc+3]
```

这里先区分两个值：

- **当前 PC**：用于取出正在执行的这条指令。
- **下一 PC**：这条指令执行完后，下一条指令的地址。

普通指令的下一 PC 是 `pc + 4`，`jalr` 的下一 PC 是跳转目标。代码或 RTL 可以同时计算这两个候选值，再用选择逻辑决定下一 PC；不要无条件先加 4 再二次修改，造成重复累加。

## 3. ID：从 32 位机器码中找出要做什么

译码阶段要回答四个问题：

1. 操作是什么：加法、加载、存储，还是跳转？
2. 需要读哪些源寄存器：`rs1`、`rs2`？
3. 是否需要写目标寄存器：`rd`？
4. 立即数在哪里，应该怎样扩展？

`add` 和 `addi` 可以形成对照：

| 指令 | 第二个操作数 | 写回 |
|---|---|---|
| `add x3, x1, x2` | 来自 `rs2` 寄存器 | `x3 ← x1 + x2` |
| `addi x3, x1, 5` | 来自指令中的 12 位立即数，符号扩展 | `x3 ← x1 + 5` |

立即数扩展不能简单理解为“截取一段位”。必须根据指令格式重新拼出立即数：本单元的 I/S 型立即数都做符号扩展；U 型把 `imm[31:12]` 放到高 20 位、低 12 位补零。本单元没有需要零扩展的指令立即数，`lbu` 的零扩展发生在 MEM 读出的数据上。

## 4. EX 和 MEM：运算结果有时是地址

以 `lw x5, 4(x2)` 为例，假设：

```text
pc = 0x80000010
x2 = 0x10000000
mem32[0x10000004] = 0x12345678
```

它的旅程是：

| 步骤 | 发生什么 |
|---|---|
| IF | 从 `0x80000010` 取出 `lw` 指令 |
| ID | 识别 `rs1=x2`、`rd=x5`、立即数 `4` |
| EX | 计算有效地址 `x2 + 4 = 0x10000004` |
| MEM | 从该地址读取 4 字节，得到 `0x12345678` |
| WB | `x5 ← 0x12345678` |
| PC | `pc ← 0x80000014` |

ALU 在这里计算的不是最终要写回的数据，而是内存地址。真正写回的值由 MEM 阶段产生。若指令改为 `lw x5, -4(x2)`，12 位立即数 `0xffc` 要符号扩展为 `0xfffffffc`，再与 `x2` 相加，而不是零扩展为 `0x00000ffc`。

`sw` 与 `lw` 前半段相似，也要计算地址，但方向相反：它从 `rs2` 取得待存数据并写内存，没有 WB 写寄存器。P0 测试程序保证 `lw/sw` 地址自然对齐；未对齐访问及异常处理留到后续阶段。

## 5. WB：并非每条指令都写寄存器

P0 的 8 条指令可以按数据流这样归纳：

| 指令 | EX 的主要工作 | MEM 的主要工作 | 是否写 `rd` |
|---|---|---|---|
| `add` | `rs1 + rs2` | 无 | 是 |
| `addi` | `rs1 + sext(imm)` | 无 | 是 |
| `lui` | 形成 `imm[31:12] << 12` | 无 | 是 |
| `lw` | 计算 `rs1 + sext(imm)` | 读取 4 字节 | 是 |
| `lbu` | 计算 `rs1 + sext(imm)` | 读取 1 字节并零扩展 | 是 |
| `sw` | 计算 `rs1 + sext(imm)` | 写入 4 字节 | 否 |
| `sb` | 计算 `rs1 + sext(imm)` | 写入 `rs2` 的低 8 位 | 否 |
| `jalr` | 计算 `(rs1 + sext(imm)) & ~1` | 无 | 是，写入旧 PC + 4 |

两个容易混淆的点：

- `lbu` 中的 `u` 表示无符号字节加载，读出的 8 位要零扩展到 32 位。
- `lui x5, 0x12345` 写入的是 `0x12345000`，不是 `0x00012345`。

所有写寄存器的指令还要遵守：`rd=x0` 时，体系结构上的 `x0` 仍保持为零。

`ebreak` 只作为 P0 仿真停机约定，不计入上述 8 条指令。minirvEMU 至少要识别它并结束执行，DUT/REF 的停机行为应保持一致。

## 6. `jalr`：同时产生返回地址和跳转目标

`jalr x1, x2, 0` 需要两个不同的值：

```text
rd  ← 当前 PC + 4
PC' ← (x2 + 0) & ~1
```

`rd` 保存的是“跳转之后应该回到哪里”，新 PC 则决定“现在跳到哪里”。因此实现时应保留当前 PC 或预先算好 `pc + 4`，不能在覆盖 PC 后再拿新 PC 计算返回地址。

按照 ISA 规则，`jalr` 会把目标地址的 bit 0 清零；在 IALIGN=32（当前没有 C 扩展，指令按 32 位对齐）的环境中，如果清零后的目标仍不满足 4 字节对齐，就会产生指令地址不对齐异常。清除 bit 0 不能替代 4 字节对齐检查。P0 不实现异常处理，测试程序保证目标 4 字节对齐即可，异常留到 P4。

## 7. 自测题

1. “取指、译码、执行、访存、写回”为什么不等同于“五级流水线”？
2. `add` 与 `addi` 的第二个源操作数分别来自哪里？
3. 在 `lw` 中，EX 阶段计算的地址和 WB 阶段写回的数据有什么区别？
4. 为什么 `sw` 没有写回寄存器这一步？
5. `jalr` 为什么不能先覆盖 PC，再用 PC 计算 `rd`？
6. `lbu` 读到字节 `0xff` 时，写入 RV32 寄存器的值是什么？
7. `lw x5, -4(x2)` 的 12 位立即数 `0xffc` 符号扩展后是什么？

<details>
<summary>参考答案（先自己回答，再展开）</summary>

1. 它们是指令的功能步骤；流水线还涉及多条指令重叠执行、流水线寄存器、冒险和控制，不是同一层面的概念。
2. `add` 来自 `rs2`；`addi` 来自指令内立即数，并做符号扩展。
3. EX 计算内存访问地址；WB 写入的是 MEM 从该地址读出的数据。
4. `sw` 的结果体现为内存状态变化，没有 `rd` 写回。
5. 此时 PC 已是跳转目标，不再是当前指令地址，会得到错误的 `pc + 4` 返回地址。
6. `0x000000ff`，因为 `lbu` 做零扩展。
7. `0xfffffffc`，即 32 位的 `-4`，不是 `0x00000ffc`。

</details>

## 8. 无需电脑的思考题

分别为下面两条指令画一张状态转移表，列出 IF、ID、EX、MEM、WB 和下一 PC：

```asm
sw x5, 8(x2)
jalr x2, x2, 0
```

要求特别回答：

- 哪一步读 `x5` 或 `x2`？
- 哪一步改变内存或寄存器？
- 第二条指令中 `rd == rs1 == x2`，读取跳转基址和写回 `x2` 的先后关系是什么？
- `jalr` 的 `rd` 和新 PC 分别使用什么值？
