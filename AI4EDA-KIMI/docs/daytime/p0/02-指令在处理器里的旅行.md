# P0 日间学习 02：指令在处理器里的旅行

> 建议用时：20~25 分钟。本单元不需要服务器。
>
> 官方讲义：[F5 支持数列求和的简单处理器](https://ysyx.oscc.cc/docs/2607/f/5.html)、[E5 迷你 RISC-V 处理器](https://ysyx.oscc.cc/docs/2607/e/5.html)。本单元先沿用 F5 的指令周期，再对应到 E5 的 minirv。
>
> 学完目标：能沿“取指 → 译码 → 执行 → 访存 → 写回”解释 P0 的 8 条指令，并单独说明 PC 如何更新。

## 1. 从 F5 的指令周期开始

官网 F5 把执行一条指令概括为：

1. **取指（fetch）**：根据当前 PC，在存储器中找到一条指令。
2. **译码（decode）**：识别操作码，并取出操作数。
3. **执行（execute）**：处理操作数，必要时更新目的寄存器或内存。
4. **更新 PC**：让 PC 指向下一条指令。

以 sISA 的 `li r0, 10` 为例：

```text
取指：从 M[PC] 取出指令
译码：识别 li，得到 rd=r0、imm=10
执行：R[0] ← 10
更新：PC ← PC + 1
```

进入 load/store 较丰富的 minirv 后，可以把“执行”进一步拆成 EX、MEM、WB 三个功能步骤：

```text
IF  取指      从 PC 指向的内存读取指令
ID  译码      识别操作，读取寄存器，生成立即数
EX  执行      算术运算、地址计算或跳转目标计算
MEM 访存      load/store 访问数据内存，其他指令直接通过
WB  写回      把结果写入目标寄存器 rd
```

PC 更新单独说明。这些功能步骤与 P0 的 RTL 模块名对应：IF/ID/EX 对应 IFU/IDU/EXU，MEM 对应 LSU，WB 对应 WBU。

**五个功能步骤不等于五级流水线。** 单周期处理器可以一次完成全部步骤，多周期处理器可以分多个周期完成，流水线则让多条指令重叠执行。

## 2. minirv 与完整 RISC-V 的关系

官网 E5 从 RV32I 中选出 8 条指令构成 minirv：

```text
add / addi / lui / lw / lbu / sw / sb / jalr
```

minirv 的其他 ISA 细节仍依据 RISC-V 手册。官网 E5 特别规定：GPR 数量与 RV32E 一致，即 16 个；完整 RV32I 则有 32 个。`x0` 始终为零，写入它不会改变其值。

当前指令长度都是 32 位，即 4 字节。RISC-V 的 PC 按字节寻址，所以顺序执行时：

```text
下一 PC = 当前 PC + 4
```

这里要区分：

- **当前 PC**：用于取出正在执行的指令。
- **下一 PC**：这条指令执行完后，下一条指令的地址。

代码或 RTL 可以同时计算 `pc+4` 和跳转目标，再选择下一 PC；不要无条件先加 4 再二次修改，造成重复累加。

## 3. ID：操作码和操作数从哪里来

译码阶段要回答：

1. 操作是什么：加法、加载、存储，还是跳转？
2. 需要读哪些源寄存器：`rs1`、`rs2`？
3. 是否需要写目标寄存器：`rd`？
4. 立即数在哪些位，应该怎样拼接和扩展？

`add` 和 `addi` 可以形成对照：

| 指令 | 第二个操作数 | 写回 |
|---|---|---|
| `add x3, x1, x2` | 来自 `rs2` 寄存器 | `x3 ← x1 + x2` |
| `addi x3, x1, 5` | 来自指令中的 12 位立即数，符号扩展 | `x3 ← x1 + 5` |

本单元的 I/S 型立即数都做符号扩展；U 型把 `imm[31:12]` 放到高 20 位、低 12 位补零。本单元没有需要零扩展的指令立即数，`lbu` 的零扩展发生在 MEM 读出的数据上。

具体编码应回到 RISC-V 官方手册查阅。官网 E5 的安排也是先 RTFM，再实现 `addi` 和 `jalr`，而不是凭印象写字段。

## 4. EX 和 MEM：地址不是最终写回的数据

以 `lw x5, 4(x2)` 为例：

```text
pc = 0x80000010
x2 = 0x10000000
mem32[0x10000004] = 0x12345678
```

它的旅程是：

| 步骤 | 发生什么 |
|---|---|
| IF | 从 `0x80000010` 取出 `lw` 指令 |
| ID | 识别 `rs1=x2`、`rd=x5`、立即数 `4` |
| EX | 计算有效地址 `x2 + 4 = 0x10000004` |
| MEM | 从该地址读取 4 字节，得到 `0x12345678` |
| WB | `x5 ← 0x12345678` |
| PC | 下一 PC 为 `0x80000014` |

ALU 计算的是内存地址，真正写回的是 MEM 读出的数据。若指令改为 `lw x5, -4(x2)`，12 位立即数 `0xffc` 要符号扩展为 `0xfffffffc`，而不是零扩展为 `0x00000ffc`。

`sw` 与 `lw` 前半段相似，但方向相反：它从 `rs2` 取得待存数据并写内存，没有 WB 写寄存器。官网 E5 允许当前实验假设 `lw/sw` 地址自然对齐，因此暂不考虑不对齐访问。

## 5. 八条指令的数据流

| 指令 | EX 的主要工作 | MEM 的主要工作 | 是否写 `rd` |
|---|---|---|---|
| `add` | `rs1 + rs2` | 无 | 是 |
| `addi` | `rs1 + sext(imm)` | 无 | 是 |
| `lui` | 形成 `imm[31:12] << 12` | 无 | 是 |
| `lw` | 计算 `rs1 + sext(imm)` | 读取 4 字节 | 是 |
| `lbu` | 计算 `rs1 + sext(imm)` | 读取 1 字节并零扩展 | 是 |
| `sw` | 计算 `rs1 + sext(imm)` | 写入 4 字节 | 否 |
| `sb` | 计算 `rs1 + sext(imm)` | 写入 `rs2` 的低 8 位 | 否 |
| `jalr` | 计算 `(rs1 + sext(imm)) & ~1` | 无 | 是，写入旧 PC + 4 |

两个容易混淆的点：

- `lbu` 的 `u` 表示无符号字节加载，读出的 8 位要零扩展到 32 位。
- `lui x5, 0x12345` 写入 `0x12345000`，不是 `0x00012345`。

## 6. `jalr`：旧 PC 和跳转目标不能混用

官网 E5 先让 minirvEMU 实现 `addi` 和 `jalr`，就是因为这两条指令已经能展示顺序执行、函数跳转和返回地址。

`jalr x1, x2, 0` 需要两个不同的值：

```text
rd  ← 当前旧 PC + 4
PC' ← (x2 + 0) & ~1
```

实现时应保留旧 PC 或预先算好 `pc+4`，不能在覆盖 PC 后再计算返回地址。若 `rd == rs1`，也要先取得旧的源寄存器值用于计算目标，再提交写回结果。

按照 ISA 规则，`jalr` 会把目标地址 bit 0 清零；在没有 C 扩展的 IALIGN=32 环境中，目标仍需满足 4 字节对齐。P0 测试程序保证目标对齐，异常处理留到 P4。

`ebreak` 只作为仿真停机约定，不计入 8 条指令。官网 E5 用它让程序决定 minirvEMU 何时结束，DUT/REF 的停机行为应保持一致。

## 7. 自测题

1. F5 的指令周期包含哪些步骤？它与五级流水线有什么区别？
2. 为什么顺序执行 minirv 指令时 PC 加 4，而 sISA 示例中 PC 加 1？
3. `lw` 中 EX 计算的地址和 WB 写回的数据有什么区别？
4. 为什么 `sw` 没有写回寄存器这一步？
5. `jalr` 为什么不能先覆盖 PC，再用 PC 计算 `rd`？
6. `lbu` 读到字节 `0xff` 时，写入 RV32 寄存器的值是什么？
7. `lw x5, -4(x2)` 的 12 位立即数 `0xffc` 符号扩展后是什么？

1. 取指、译码、执行和更新 PC；这些是指令的功能步骤，流水线还涉及多条指令重叠执行、流水线寄存器和冒险控制。
