## 4. 当前 NPC 架构

当前版本正式命名为：**单周期无访存延迟NPC**。

活跃代码：

```text

```

稳定旧备份：

```text

```

后续开发只修改活跃 `ysyx-workbench/npc`，不要修改备份。

当前结构：

- 单周期 minirv，支持 `add/addi/lui/lw/lbu/sw/sb/jalr`，不扩展 M 扩展，除非用户明确要求。
- IFU/LSU 共用 `pmem_read()`，DUT 和 REF 使用统一的 128 MiB PMEM，程序从 `0x80000000` 启动。
- `main.cpp` 从命令行接收 `.bin`，DUT 和 minirvEMU 逐指令比较 PC、取指和 `x0~x15`，保留最近 16 条历史。
- UART 数据地址为 `0x10000000`，`putch()` 通过 volatile `sb` 输出。
- 计时器低/高 32 位地址为 `0x20000000`、`0x20000004`。
- AM `__am_timer_uptime()` 使用“高—低—高”方式读取 64 位微秒时间。
- 当前默认频率为 100MHz：`get_time() = cycle_count / 100`，不是宿主机时间。
- DUT 执行和 REF 对比之后调用 `pmem_tick()`，保证双方读取同一周期值。
- 默认 `max_cycles=110000000`，可用 `NPC_MAX_CYCLES` 覆盖。

PMEM/UART 写目前使用临时仿真调度：低电平观察写请求，高电平最多提交一次，不读取 PC 或 opcode。这是为了避免组合逻辑 DPI 重复副作用，后续用户准备将 LSU 写调用移到 `posedge clk` 的有效写事务中，再删除该写窗口。
