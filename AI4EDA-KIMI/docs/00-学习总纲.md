# CPU 设计学习计划 v2（MCU 外设工程师 → CPU 设计）

> 目标：系统掌握 CPU 微架构设计，产出可展示的全流程项目，为跳槽 CPU 设计岗位做准备
> 方式：自学（参考"一生一芯"公开资料，不参加官方项目）+ AI 辅助加速
> 周期：约 16~20 周（按每周 8~10 小时估算，可按节奏伸缩）
> v2 变更：按实际背景（外设设计为主，无核内经验）重排路径，先直觉后实现

## 一、背景与能力校准（v2）

**实际经历**：MCU 外设前端设计——PWM（定时器/比较器）、CAN/LIN（协议控制器）、
寄存器接口、AHB/APB 从设备、外设侧中断；做过 AXI4 Master + 仲裁器练手项目。

**已有优势**：
- RTL 编码与仿真调试功底扎实（FSM 是外设设计的基本功，而 CPU 控制器本质也是 FSM）
- 总线协议的从设备视角经验 + AXI4 Master 练手 → SoC/总线阶段是舒适区
- 外设中断源设计经验 → 学核内中断处理有外设端的对照系
- 了解综合/时序基本概念

**真正盲区**（学习重点）：
- 微架构：流水线、冒险、前递、分支预测、cache——几乎零基础
- ISA 视角：写 C 用 MCU 但从没认真读过汇编/机器码，"C↔指令↔执行"链条断裂
- 工具链底层：编译/链接/ELF、golden model、difftest 等概念
- "处理器设计师"的心智模型（这是本计划要逐步建立的）

**目标岗位画像**：平头哥/芯来/赛昉/奕斯伟/海思/玄戒/展锐等的 CPU 前端设计岗位。

## 二、最终交付物（面试作品集，不变）

带 I/D Cache 的五级流水线 RV32IM CPU（自有命名），AXI4 接口、CLINT、
Difftest 验证、coremark 跑分报告、yosys 综合数据。
**变化的是路径，不是目标**——岗位要求的最终形态不变。

## 三、学习策略（v2 核心调整）

1. **先跑起来，再拆开来**：先用模拟器观察程序逐条执行，建立直觉，再学编码细节
2. **熟悉锚点教学法**：
   - 流水线停顿/反压 → 类比 AHB wait state / valid-ready 反压（你写过）
   - CPU 控制器 → 类比你写过的外设 FSM，只是状态多一点
   - 中断 → 从你熟悉的外设中断源视角切入核内视角
   - Cache → 唯一完全陌生的概念，放足时间
3. **小步交付**：每个阶段有"最小可见成果"，避免长期看不到产出
4. **AI 角色前移**：前半程我主导讲解你动手复现；后半程翻转为你主导我 review

## 四、阶段规划（v2）

### P0a 程序是如何跑起来的（第 1~2 周）★全新起步
- 在 spike 上运行 C 程序，打印**每一条执行的指令**，观察寄存器/内存变化
- 最小指令集：addi/add/sub、lw/sw、beq/bne、jal/jalr（约 15 条够用）
- C 函数 ↔ 汇编 ↔ 机器码 三方对照（gcc 编译、objdump 反汇编）
- 手写小程序：累加、数组遍历、函数调用，跑通"写-C→看汇编→看执行"
- **交付**：能读懂 30 行内汇编；能口述"取指→译码→执行→访存→写回"这条循环
- **验收**：给你一段 C 和它的反汇编，你能逐行解释机器在干什么

### P0b 指令集全貌（第 3~4 周）
- 补全 RV32I 其余指令 + M 扩展；这时候再学六种**编码格式**（有使用直觉垫底，
  字段设计取舍才讲得进去）
- 寄存器惯例（ra/sp/a0-a7/t/s 系列）与调用约定
- 特权架构初识：M 模式、CSR 寄存器混脸熟（P4 展开）
- **交付**：docs/p0-isa-notes.md 填完；47 条指令能分类说出用途

### P1a CPU = FSM + 数据通路（第 5~6 周）★降低坡度
- 概念课：数据通路五大部件（PC/寄存器堆/ALU/存储器/控制）——全是外设里见过的积木
- **多周期**最小核：只支持 lw/sw/addi/bne 的玩具 CPU（几十行 RTL）
  ——控制方式就是写外设 FSM 的方式，一周期做一件事
- 跑通 P0a 的累加程序：在自己写的核上运行
- **交付**：玩具核 + 仿真波形 + "指令在核里的旅行"笔记
- **验收**：能指着波形说每个周期 FSM 在哪个状态、哪些信号有效

### P1b 单周期全 RV32I + Difftest（第 7~9 周）
- 单周期数据通路铺开全 47 条指令（写代码前我先给设计方案，你 review 后动手）
- Verilator 仿真环境搭建
- **Difftest 框架**：RTL 对照 golden model 逐指令比对（新概念，我搭脚手架你理解）
- **交付**：全指令单周期核，随机指令流 difftest 通过
- **面试映射**："一条指令的执行全过程"标准题

### P2 五级流水线（第 10~13 周）★核心硬仗
- 概念铺垫：为什么流水 → 吞吐 vs 延迟；三级→五级
- 数据冒险：前递（forwarding）——用反压思维理解"等数据还是绕道送数据"
- Load-use、控制冒险（分支预测基础：总是不跳/总是跳/饱和计数器）
- **交付**：流水线核 + IPC 分析报告
- **AI 加速**：我生成冒险定向测试（随机指令流+种子库），帮你从波形定位 bug

### P3 存储层次（第 14~16 周）——你的相对舒适区
- I$/D$ 概念（全新，放慢）：tag/data、命中/缺失、写策略
- AXI burst refill——复用 archive/ 的 AXI4 Master 经验
- fence、uncached MMIO
- **交付**：带 cache 完整核 + coremark 跑通 + 命中率扫描报告

### P4 中断与系统（第 17~18 周）
- 从外设中断源视角切入：你发的中断信号，核内经历了什么
- CLINT、异常精确性、上下文保存、双任务轮转
- **交付**：中断全场景测试

### P5 性能优化 + P6 求职收尾（第 19~20 周）
- 分支预测进阶、coremark/MHz 迭代优化、yosys 综合
- 简历包装 + 模拟面试（我出题）

### 支线 S1：AI 加速器——权重硬化实验（第 14 周起与主线并行）★求职加成项
- **定位**：面向 AI 芯片设计岗位的加分项目，不影响主线节奏；
  启动条件为 P2 五级流水线完成（需要流水线/冒险/验证功底）
- **核心问题**：把一个小尺寸大模型的权重"烧成硬件"值不值？
  用两个版本的设计对比来回答，而不是空谈：
  1. **可编程版**：INT8 transformer 加速器（GEMM 阵列 + 片上 SRAM + AXI4 从接口），
     权重可加载，跑 stories15M 级小模型（llama2.c 做 golden 对照）
  2. **硬连线版**：同一模型，权重烧 ROM / 综合成常数逻辑
  3. **PPA 对比报告**：yosys/OpenLane + Sky130，量化"烧权重"换来的
     面积/功耗/能效收益与灵活性代价——这正是面试该讲的架构判断
- **复用主线资产**：AXI4 Master/仲裁经验（archive/）、difftest 框架（P1b）、
  Verilator 环境；P3 后可挂载到主线 CPU 核组成小型 AI SoC
- **流片（可选）**：TinyTapeout（Sky130 开源工艺，提交 GDS 即可，无需本地硬件）
- **交付**：加速器 RTL + difftest 报告 + PPA 对比报告（+ 可选流片芯片）
