# 学习线：处理器设计路线（一生一芯 v26.07 逐章对齐版）

> 本文档是学习线主线，总入口见 `docs/00-学习总纲.md`。
> 官方目录：[一生一芯 v26.07](https://ysyx.oscc.cc/docs/2607/)。
> 本版以官网 F→E→D→C→B→A 的章节和依赖关系为主轴，P0~P9 只是项目内的阶段封装。
> 每个官方章节都必须有明确去向，不再把未出现的章节视为默认跳过。

## 一、背景与路线原则

**已有基础**：MCU 外设前端设计，做过 PWM/CAN/LIN、寄存器接口、AHB/APB 从设备和外设中断，具备 RTL 编码、仿真调试和从设备侧总线经验。

**主要缺口**：

- 从 ISA 到处理器数据通路、控制逻辑的完整设计闭环。
- C 语言系统软件、指令集模拟器、调试器、AM、编译链接和 ELF。
- AXI 主设备、存储系统、异常、cache、流水线和性能分析。
- 从 RTL 到网表、物理设计和签核的完整流程。

**路线原则**：

1. **官网章节是主线**：学习包是辅助摘要，不能替代官方讲义、PA 和手册。
2. **保持前置关系**：sISA/sCPU → RTL 仿真与 minirv → AM/SoC → NEMU/RV32E NPC → 总线/设备/SoC → 异常 → cache → 流水线。
3. **先完成，后完美**：先让处理器在真实 SoC 中运行，再用性能数据决定 cache、流水线和预测等优化。
4. **基础设施先行**：仿真、批量测试、trace、DiffTest 和性能计数器是设计工具，不是最后补的附属品。
5. **功能与性能分别验证**：功能正确不代表性能符合预期；cachesim/branchsim 和性能计数器用于发现性能 bug。
6. **设计决策由本人作出**：AI 负责讲解、脚手架和 review；模块接口、验证条件、优化取舍和实验结论必须由本人说明。

## 二、怎样使用官方课时与个人基础

官网 F/E/D/C/B 的参考总课时为 **290h**。它按“中等水平”估计，不是本项目必须压缩完成的期限，也不等于个人实际耗时。

- F1 必读，建立提问和求证方式。
- F2/F3 可依据已有数字电路基础做诊断式复习，但 F5/F6 的 sCPU 实验不能因此省略。
- E1/E3 可减少重复的 HDL、Linux 基础练习，以 E4 的实际操作验收。
- E2 不能仅因“会 C 语法”而跳过；PA1、NEMU 和 AM 是检验 C 系统编程能力的实际任务。
- 官网标注“讲义未就绪”或“建设中”时，以该页指定的 PA、课件和视频为准，不把标题自行扩写成官方实验。
- 进度以交付物和验收问题为准，不再用“第几周必须完成”倒逼跳章。求职冲刺期降速，但不打乱依赖顺序。

## 三、最终交付物

完成 B 阶段主线后，形成以下可展示成果：

- sCPU、minirvEMU 和 minirv NPC 的早期学习记录。

## 五、逐阶段计划

### P0 状态机与 sCPU：F1~F6

**目标**：先用一个小到可以手工追踪的 ISA，完整经历“规范 → 程序 → 数据通路 → 控制逻辑 → 输入输出”。

- [F1 如何科学地提问](https://ysyx.oscc.cc/docs/2607/f/1.html)：问题要包含现象、最小复现、已查手册和已做实验，不用猜测代替证据。
- [F2 Logisim 安装和使用](https://ysyx.oscc.cc/docs/2607/f/2.html)：按实验需要查阅工具操作。
- [F3 数字逻辑电路基础](https://ysyx.oscc.cc/docs/2607/f/3.html)：重点核对补码、溢出、译码器、多路选择器、加法器、锁存器、触发器和寄存器；已有基础部分不重复刷题。
- [F4 计算机系统的状态机模型](https://ysyx.oscc.cc/docs/2607/f/4.html)：手工执行 sISA 数列求和；用状态集合、激励事件、转移规则和初始状态统一理解 C 程序、ISA 和数字电路。
- [F5 支持数列求和的简单处理器](https://ysyx.oscc.cc/docs/2607/f/5.html)：依次实现 `li`、`add`、`bner0`；理解 ROM/RAM、GPR 读写在电路上的实现，以及数据通路和控制信号。
- [F6 简易输入输出](https://ysyx.oscc.cc/docs/2607/f/6.html)：实现增强版 `li`、PC 相对 `bner0` 和 `io`；理解符号扩展、设备编号、输出保持寄存器，以及为什么从 Logisim 转向 HDL。

**交付**：Logisim sCPU 运行数列求和；增强指令测试；LED/数码管/开关/按钮实验；自己的状态转移表和控制信号表。

**验收**：能解释 `bner0` 的下一 PC 选择、`li` 的移位立即数、输出设备为什么需要寄存器，以及“改程序”和“改硬件”分别能解决什么问题。

### P1 RTL 仿真与 minirv：E1~E5

**目标**：从图形化电路过渡到现代 RTL 仿真流程，用两种实现执行同一个迷你 RISC-V ISA。

- [E1 硬件描述语言](https://ysyx.oscc.cc/docs/2607/e/1.html)：按个人缺口复习，验收放在 E4 的实际 RTL 和仿真中。
- [E2 C 语言程序设计](https://ysyx.oscc.cc/docs/2607/e/2.html)：围绕后续模拟器所需补弱，包括指针、数组、位运算、内存模型、未定义行为和调试。
- [E3 Linux 系统安装和基本使用](https://ysyx.oscc.cc/docs/2607/e/3.html)：按操作诊断补缺，不重复已经熟练的命令。
- [E4 处理器的仿真和验证](https://ysyx.oscc.cc/docs/2607/e/4.html)：搭建 Verilator、波形、Makefile、NVBoard 和 lint；完成数字电路实验；用 RTL 实现 sCPU；编写 sEMU 并进行 sCPU↔sEMU DiffTest，注入错误检查比较机制。
- [E5 功能完备的迷你 RISC-V 处理器](https://ysyx.oscc.cc/docs/2607/e/5.html)：实现 minirvEMU，再用模块化 RTL 实现 minirv NPC；按 `addi/jalr → 完整 8 条指令 → ebreak` 的顺序推进。

**交付**：可重复的 Verilator 仿真环境；minirvEMU 和 minirv NPC；逐条指令日志；PC/GPR 比较和故障注入记录。

**验收**：能说明五个功能步骤为什么不是五级流水线、旧 PC 与下一 PC 的区别、DiffTest 的比较边界，以及 REF 为什么也可能错误。

### P2 最小系统闭环：E6~E8

**目标**：让 minirv 从“执行手工指令序列”变成能编译、加载、测试、访问设备、接入 SoC 并评估物理实现的完整小系统。

- [E6 简易运行时环境](https://ysyx.oscc.cc/docs/2607/e/6.html)：体验 AM；运行 `dummy`；通过 `halt/ebreak/a0` 和 Makefile 建立批量测试；运行 `riscv-tests/cpu-tests`；接入 minirvEMU DiffTest 并注入错误；实现 UART 和时钟行为模型；运行 benchmark/archbench；区分功能测试的 `test` 规模与性能评估的 `train` 规模；用 ECC 综合结果校准频率。
- [E7 简易总线和 SoC](https://ysyx.oscc.cc/docs/2607/e/7.html)：从 DPI-C 零延迟访存演进到 SimpleBus 和随机延迟；接入 minirv 版 ysyxSoC；适配 UART16550 和 GPIO；实现标识 CSR、`mcycle/mcycleh`；测量 IPC、校准 NPC/外设频率比例，分析频率提升为何可能被访存抵消。
- [E8 后端物理设计和流片准备](https://ysyx.oscc.cc/docs/2607/e/8.html)：检查地址空间、双边沿时钟、锁存器和 lint；理解最小复位集合；用 iverilog 做四值仿真；完成 RTL 与网表仿真；用 ECOS Studio 完成一次物理设计和签核包导出。

**交付**：AM 编译运行与批量回归；UART/时钟程序；SimpleBus+SoC 测试；IPC/频率/面积记录；四值和网表仿真记录；一次 ECOS Studio 物理设计结果。

**验收**：能解释 MMIO 与 F6 专用 `io` 指令的区别、`HIT GOOD/BAD TRAP` 怎样传回 Makefile、为什么功能仿真和性能仿真可以采用不同环境，以及综合频率为什么不是最终芯片频率。

### P3 程序、NEMU 与 AM：D1~D5

**目标**：系统补齐软件半边，把 minirvEMU 的经验扩展为 RV32IM NEMU，并理解程序从源代码到裸机执行的全过程。

- [D1 从 C 代码到二进制程序](https://ysyx.oscc.cc/docs/2607/d/1.html)：预处理、编译、汇编、链接和执行；C 标准的未指定、实现定义和未定义行为；ABI 的基本作用。
- [D2 简易调试器](https://ysyx.oscc.cc/docs/2607/d/2.html)：按官网要求完成 PA1，包括 NEMU 基础设施、sdb、表达式求值、监视点和必答题。
- [D3 RISC-V 指令集](https://ysyx.oscc.cc/docs/2607/d/3.html)：按官网要求完成 PA2 阶段 1，实现支持 RV32IM 的 NEMU；结合手册理解指令语义，不停留在指令表背诵。
- [D4 程序的机器级表示](https://ysyx.oscc.cc/docs/2607/d/4.html)：按官网课件和视频学习数据表示、控制流、函数调用和 ABI，配合 C↔汇编实验。
- [D5 AM 运行时环境](https://ysyx.oscc.cc/docs/2607/d/5.html)：按官网指定内容完成 PA2 的“程序、运行时环境与 AM”，理解 TRM 和硬件抽象。

**交付**：NEMU+sdb；RV32IM 指令测试；C/汇编/机器码对照笔记；AM 上的 `dummy` 和基础测试。

**验收**：能逐层解释 C→汇编→ELF→加载→指令执行；能使用 sdb 定位一条错误指令；能说明 AM 为什么可以让同一程序面向不同平台构建。

### P4 RV32E NPC 与基础设施：D6~D8

**目标**：先建立观察、调试和评估能力，再把 minirv NPC 扩展为 RV32E NPC，同时理解 RTL 到物理实现的完整语义。

- [D6 从 RTL 代码到可流片版图](https://ysyx.oscc.cc/docs/2607/d/6.html)：事件驱动仿真、层次化事件队列、阻塞/非阻塞赋值和数据竞争；逻辑综合与 RTL 综合语义；面积/性能/功耗评估；PDK、标准单元、PVT；Floorplan、Powerplan、Placement、CTS、Routing 和 Sign-off。
- [D7 工具和基础设施](https://ysyx.oscc.cc/docs/2607/d/7.html)：官网正文未就绪时，严格按该页指向完成 PA2 阶段 2，不自行缩减基础设施任务。
- [D8 支持 RV32E 的 NPC](https://ysyx.oscc.cc/docs/2607/d/8.html)：先为 NPC 搭建基础设施，再实现 RV32E；接入 NEMU 作为 DiffTest REF，明确指令提交边界，使用 trace 和批量回归定位问题。

**交付**：RV32E NPC；sdb/itrace/mtrace/ftrace；NEMU↔NPC DiffTest；随机指令流和故障注入；D6 概念图及评估报告。

**验收**：能解释仿真与综合语义差异、为什么 `riscv-tests` 通过仍不够、DiffTest 如何适配并非每周期提交一条指令的处理器。

### P5 链接、设备与调试：C1~C3

**目标**：在进入完整 SoC 前补齐链接和设备输入输出，保留专门的调试方法复盘。

- [C1 ELF 文件和链接](https://ysyx.oscc.cc/docs/2607/c/1.html)：官网正文未就绪时使用其课件和视频；结合已有 ELF、反汇编和链接实验整理疑问，不虚构额外官方编程任务。
- [C2 设备和输入输出](https://ysyx.oscc.cc/docs/2607/c/2.html)：体验 AM 的 GUI 输入输出，完成屏保或小游戏练习；为 NPC 添加输入输出支持，并在 NPC 上运行红白机游戏。
- [C3 调试技巧](https://ysyx.oscc.cc/docs/2607/c/3.html)：官网正文未就绪时使用其课件和视频；把方法应用到当前真实 bug，记录从现象、假设、实验到根因的过程。

**交付**：ELF/链接笔记；NPC 设备测试；一个真实 bug 的完整调试复盘。

**验收**：能解释设备行为模型和真实设备控制器的边界，以及为什么“能输出字符”不代表已具备完整输入输出能力。

### P6 总线与完整 SoC：C4~C5

**目标**：把处理器、存储器和设备连接成可流片形态，并从单周期走向握手控制的多周期 NPC。

- [C4 总线](https://ysyx.oscc.cc/docs/2607/c/4.html)：从 `valid/ready` 理解模块间通信和分布式控制；将 SimpleBus 扩展为请求/响应完整握手；用随机延迟测试；实现 AXI4-Lite、Arbiter、Xbar、UART 和 CLINT；理解死锁、活锁、错误响应和 PMA 的基本作用。
- [C5 SoC 计算机系统](https://ysyx.oscc.cc/docs/2607/c/5.html)：接入完整 ysyxSoC；理解 MROM/SRAM、Flash、PSRAM、SDRAM、loader/bootloader、VMA/LMA；完成内存测试、串口和更多外设；按官网任务运行 AM 程序和 RT-Thread 相关内容。

**交付**：多周期 AXI4-Lite NPC；仲裁与地址译码；完整 SoC 回归；存储器和启动流程图。

**验收**：能讲清一次 load 从 LSU 到存储颗粒再返回的全过程；能解释单周期、多周期和流水线为什么可以复用同一套模块通信思想。

### P7 异常、OS 与时序：B1~B2

**目标**：让软件可见的异常和操作系统真正运行在自研 NPC 上，并建立时序优化意识。

- [B1 异常处理和简易操作系统](https://ysyx.oscc.cc/docs/2607/b/1.html)：先在 NEMU 中运行 RT-Thread，再为 NPC 添加 CSR，最后在 NPC 中运行 RT-Thread；按手册实现所需异常和中断行为。
- [B2 时序分析和优化](https://ysyx.oscc.cc/docs/2607/b/2.html)：官网页面建设中且暂无编程内容；使用现有资料理解时序分析，并将后续真实优化记录到本阶段。

**交付**：NEMU/NPC 的 RT-Thread 运行记录；异常测试；关键路径和时序优化笔记。

**验收**：能解释 `mepc/mcause/mtvec/mstatus` 在一次异常中的作用，以及为什么模拟器先跑通 OS 能降低 RTL 调试复杂度。

### P8 性能与 cache：B3

**目标**：先量化，再优化；把功能正确的 SoC 变成有性能数据支撑的体系结构设计项目。

- 按 [B3 性能优化和简易缓存](https://ysyx.oscc.cc/docs/2607/b/3.html)完成：
  - 使用有代表性的 benchmark，区分功能测试和性能测试，保留基线数据。
  - 用性能公式、IPC、性能事件和 Amdahl 定律寻找瓶颈，校准访存延迟。
  - 理解存储层次、局部性和 AMAT；先实现简易 icache。
  - 使用 `assert/assume` 和 BMC 验证 icache；理解形式化验证的能力与状态空间爆炸边界。
  - 用 NEMU 生成 trace，实现 cachesim；探索容量、相联度、块大小、缺失代价、AXI burst 和内存布局。
  - 用性能计数器和 cachesim 交叉检查性能 bug。
  - 在实现 dcache 前先评估理想收益、面积和性价比，可以基于数据决定不实现。
  - 复现自修改代码和 bootloader 的缓存一致性问题，实现并验证 `fence.i`。

**交付**：icache；cachesim；性能计数器；形式化验证报告；参数探索和 `fence.i` 测试；优化前后对比。

**验收**：能解释“功能 DiffTest 通过但 cache 一直缺失”为什么仍是 bug，以及为什么提升频率不一定缩短程序运行时间。

### P9 流水线：B4

**目标**：在已有 SoC、icache 和性能数据上演进流水线，而不是脱离系统单独画一张五级流水框图。

- 按 [B4 流水线处理器](https://ysyx.oscc.cc/docs/2607/b/4.html)完成：
  - 先估算 dcache 和提升计算效率的理想收益，再决定是否进入相应 RTL 优化。
  - 基于握手机制实现基本流水线，处理结构、数据和控制冒险。
  - 实现推测执行的选择、检查和恢复；处理精确异常及流水线中的 `fence.i`。
  - 调整 DiffTest 的指令提交边界；用有针对性的指令序列验证冒险。
  - 按官网强烈建议，以单周期 NPC 为 REF，用 BMC 遍历有界指令序列，仔细设计 `assert/assume`。
  - 用性能计数器定位指令供给、数据供给和计算效率瓶颈。
  - 实现转发这一必做优化；比较转发到 ID 与教科书转发到 EX/LS 的差异。
  - 用 branchsim/btrace 评估 BTFN、BTB 等方案，再决定是否实现；其他优化同样以面积、频率和 IPC 数据取舍。

**交付**：支持异常和 `fence.i` 的流水线 NPC；转发；形式化验证记录；多周期与流水线的性能对比和瓶颈归因。

**验收**：能解释 load-use、最年轻转发源、错误推测为什么不能更新架构状态，以及为什么真实 SoC 中流水线未必带来理想倍数加速。

## 六、A 阶段与自选支线

### A 阶段延伸

官网当前列出的方向为：乘除法器、系统调用和应用程序、虚存管理、特权级和 xv6、启动 Linux 和 Debian、缓存进阶、分支预测进阶。官网未给出统一课时，本计划不虚构其详细讲义内容。

建议顺序：

1. 乘除法器，补齐 M 扩展硬件实现。
2. 系统调用和应用程序。
3. 特权级、虚存和 xv6。
4. 启动 Linux/Debian。
5. 缓存和动态分支预测进阶。

每一步先回到当时官网和对应手册确认任务，再单独制定交付物。

### 支线 S1：AI 加速器（项目自选，不属于官方主线）

在 B4 后启动，避免挤占 F~B 的前置学习。

- **问题**：把小模型权重硬化为硬件是否值得。
- **可编程版**：INT8 transformer 加速器、GEMM 阵列、片上 SRAM、AXI4 接口，用 llama2.c 等作为 golden 对照。
- **硬连线版**：权重放 ROM 或综合成常数逻辑。
- **比较**：功能正确性、性能、面积、功耗、灵活性和存储带宽。
- **原则**：复用主线的 DiffTest、总线、trace 和量化方法，不用一个孤立的 RTL 模块代替系统论证。

S 阶段官网仍为待续，不纳入当前计划。
